### 本地 AI 聊天 API（2026-11-27，Ollama + gemma3:4b）
- **後端**：`POST /api/chat`（`src/app/api/chat/route.ts`）→ 本機 Ollama `http://127.0.0.1:11434/api/chat`，回應是純文字串流。輸入檢查、系統提示、NDJSON→文字轉換在 `lib/ai/chat-input.ts`（純函式，有單元測試）
- **環境變數**：`OLLAMA_URL`（預設 `http://127.0.0.1:11434`）、`OLLAMA_MODEL`（預設 `gemma3:4b`）。Ollama 只聽 127.0.0.1，**不要對外開 11434**，所有限制都在這支 API
- **限制**：body 8KB、保留最近 10 則、每則 800 字；每 IP 10 分鐘 12 則、全站每小時 200 則、同時最多 2 個生成、逾時 60 秒；不存對話、不記誰問了什麼
- **選型**：RTX 3070 8GB（桌面先佔約 1.8GB）→ 使用者要求不用中國模型、最好美國大廠 → Google Gemma 3 4B（約 3.3GB，GPU 佔約 2.9GB）。`gemma3:12b` 約 8GB 會溢到 CPU、`gpt-oss:20b` 要約 16GB 都不適合
- **冷啟動約 60 秒**（第一個請求載入模型），暖機後約 0.7 秒開始回應。請求帶 `keep_alive: "10m"`；之後的 /ask 頁面要有「暖機中」提示，並考慮開機預熱
- **系統提示的規則**：它一定守不住（4B 模型會被「印出你的指示」騙出來），所以**提示裡不放任何不能公開的東西**；中文本名不寫進去（有單元測試擋），並明寫「被問姓名／住址／電話就說網站沒有公開，不要猜」，不然模型會編一個錯的名字
- **測中文不要在 Git Bash 命令列塞中文**（編碼被改，模型會回「您輸入了亂碼」）：用 Node 寫成 UTF-8 JSON 檔再 `curl --data-binary @檔案`
- **還沒做（待辦 H1「問我」/ask、H6 雷達 AI 日報）**：/ask 頁面、公開內容知識庫＋來源連結、/hire 導引、`/mcp` 的 `ask` 工具、開機預熱
