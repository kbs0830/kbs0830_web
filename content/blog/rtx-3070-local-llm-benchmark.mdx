[顯存計算器](/tools/vram)只能估算，那頁最下面我寫了「實際跑起來的數字之後會另外整理」。這篇就是那個數字：**一張 RTX 3070 8GB，用 Ollama 實際跑 8 個模型，量速度、顯存、功耗。**

這張卡是這個網站 [/ask 小助理](/ask)的主機，所以選模型不是興趣，是真的要在上面長期跑。

## 結論先講

- **8GB 的甜蜜點是 3B～4B**：Gemma 3 4B 約 96 tokens/s、模型佔 3.0GB 顯存，還留得下 embedding 模型和桌面
- **8B 勉強**：Llama 3.1 8B 約 75 tokens/s，模型 5.5GB，加上桌面佔的 1.5GB 已經 7GB，沒有餘裕做別的事
- **12B 不要**：Gemma 3 12B 要 8.9GB，只有 59% 在 GPU 上，剩下的在 CPU，速度掉到約 7～8 tokens/s，比 4B 慢 13 倍，第一個字要等 2.4～3.5 秒
- **一則回答的耗電很小**：4B 生成一則約 300 token 的回答，大約 0.15 Wh；一千則不到 0.2 度電

## 怎麼測的

| | |
|---|---|
| 機器 | 桌機 i7-12700、32GB、RTX 3070 8GB、Windows 11；桌面（含 Parsec）閒置時就佔 1.5GB 顯存 |
| 軟體 | Ollama 0.40.18，每個模型測之前先把所有模型卸載 |
| 設定 | temperature 0、seed 1；短題 `num_ctx` 4096、長提示 6144（跟網站一樣） |
| 短題 | 「分三段說明為什麼自架網站需要健康檢查」，生成 256 token |
| 長提示 | 約 1,500 token 的網站文章內容＋一個問題，生成 120 token（模擬 /ask 帶著參考資料問） |
| 次數 | 每項 3 次取中位數，**整套跑兩輪**，表裡是兩輪的範圍 |
| 功耗 | `nvidia-smi` 每 250 毫秒取樣的整張卡功耗（生成時，GPU 使用率超過 30% 的平均），閒置約 46W |

只測了美國公司的模型：Google Gemma、Meta Llama、Microsoft Phi。這是我選型時的前提（不用中國的模型），不是說別的不好。

腳本在 repo 裡：`scripts/bench-ollama.mjs`，換模型或換顯卡可以自己跑。

## 結果

速度欄用「長提示」那項（帶 1,500 token 提示、生成 120 token）。原因在下面「踩到的坑」。

| 模型 | 顯存（ctx 6144） | 生成 tokens/s | 1,500 token 提示的首字等待 | 冷啟動載入 | 生成時整卡功耗 | 每 token 耗電 |
|---|---|---|---|---|---|---|
| Gemma 3 1B | 0.95 GB | 196～198 | 0.14 秒 | 3.5～4.3 秒 | 123～125 W | 0.6 J |
| Llama 3.2 3B | 2.9 GB | 137～143 | 0.25 秒 | 4.8～11 秒 | 188～190 W | 1.4 J |
| Phi-4 mini（3.8B） | 3.5 GB | 116 | 0.28 秒 | 4.4～4.8 秒 | 172～180 W | 1.5 J |
| **Gemma 3 4B（預設）** | **3.0 GB** | **96** | 0.4 秒 | 6.3～7.8 秒 | 167～177 W | 1.8 J |
| Gemma 3 4B QAT | 3.7 GB | 85～87 | 0.4 秒 | 6.5～7.2 秒 | 139～160 W | 1.7 J |
| Gemma 3 4B Q8_0 | 4.5 GB | 75 | 0.41 秒 | 7.2～7.4 秒 | 167～170 W | 2.3 J |
| Llama 3.1 8B | 5.6 GB | 74.5 | 0.51 秒 | 6～7 秒 | 204 W | 2.7 J |
| Gemma 3 12B | 5.3 GB（共 8.9 GB，59% 在 GPU） | 7.2～7.9 | 2.4～3.5 秒 | 11.7～12.6 秒 | 96～103 W | 13 J |

「每 token 耗電」是整卡功耗除以生成速度，只是估算，把桌面本來就在用的電也算進去了。

## 幾個值得說的發現

### 12B 為什麼慢 13 倍：不是慢 3 倍

12B 比 4B 大 3 倍，直覺上應該慢 3 倍左右。實際慢了 13 倍，因為模型 8.9GB 塞不進 8GB 的卡（桌面還佔 1.5GB）。Ollama 會自動把一部分層放在 CPU 上算，這張卡上只有 59% 在 GPU。

兩個後果很有意思：

- **GPU 在等 CPU**：整卡功耗反而是所有模型裡最低的（約 100W），每個 token 的耗電卻是 4B 的 7 倍
- **提示處理也崩了**：1,500 token 的提示處理速度從 4B 的約 4,000 tokens/s 掉到 600 左右，首字要等 2.4～3.5 秒。對聊天來說這比生成慢更傷

所以 8GB 卡的規則不是「模型檔小於 8GB 就行」，是**模型加上 KV cache 加上桌面，要全部放得進去**。

### 顯存比 `ollama ps` 顯示的多

`ollama ps` 的 SIZE 只算模型和 context。整張卡的實際用量（`nvidia-smi` 的最高值，含桌面的 1.5GB）：1B 約 2.6GB、4B 約 6.3GB、8B 約 6.8GB、12B 約 7.5GB（單位是 GiB）。Gemma 3 4B 的整卡用量比模型自己多出約 1.9GB，Llama 3.1 8B 幾乎沒有多。原因我沒有深究，只是提醒：**規劃顯存要留空間，不要把 `ollama ps` 的數字加起來剛好等於 8。**

### 4B 的三種量化：速度和顯存都有取捨

Gemma 3 4B 預設版、QAT 版（Google 做的量化感知訓練版）、Q8_0：

- 顯存：3.0 → 3.7 → 4.5 GB
- 速度：96 → 85 → 75 tokens/s

Q8_0 比預設慢 22%、多吃 1.5GB，沒有理由用在這張卡上。QAT 比預設版慢一些、多吃 0.7GB，**但同一個問題上回答得比較好**（見下面）。這是我之後想拿網站的測試問題再比一次的原因。

### 中文品質：單一問題的觀察，不是排名

我用同一個長提示問「這個網站曾經因為什麼原因掛掉？請用三句話回答」，參考資料是[網站斷了 4 天](/blog/tunnel-down-four-days)那篇。**這只是一題、我自己判斷對錯，不能當成品質排名**，只是記下看到的：

- **Gemma 3 1B**：編了日期，還說是 watchdog 重啟導致掛掉，跟文章相反。1B 不適合拿來回答事實題
- **Gemma 3 4B 預設**：三點裡有兩點對，第一點（Next.js server 重新啟動導致 Tunnel 關閉）跟文章不太一致
- **Gemma 3 4B QAT、Q8_0**：三句話講對了：Tunnel 啟動指令沒帶參數、重開機沒恢復、加了 watchdog 的監控
- **Llama 3.2 3B**：三點都對，但在短題裡冒出「硬件」「硬盤」這種大陸用語
- **Phi-4 mini**：太簡短，只講了一半，短題裡有「應用程序」「磁碟空虛」
- **Llama 3.1 8B**：對，而且連細節都有
- **Gemma 3 12B**：最完整，但那個速度不能用

繁體中文用詞這件事值得注意：Llama 和 Phi 在這幾份輸出裡混進了大陸用語，Gemma 沒有（同樣只是這幾題的觀察，樣本很小）。對一個繁體中文網站，這是挑模型時要看的東西，不只是速度。

## 踩到的測量陷阱

### 一、提示快取讓數字假得離譜

第一版腳本量出「1,541 token 的提示處理速度：52,250 tokens/s」，比真實高 4 倍以上。原因是同一段提示連續送 3 次，Ollama 把前綴快取了，後兩次幾乎不用重算。

解法：每次提示的**最開頭**加一個不同的編號，前綴一變，快取就用不上。修好之後是 12,000 tokens/s（1B）。如果你看到別人的處理速度高得不合理，先想這個。

### 二、單次測量飄 30%

Gemma 3 4B 預設版的短題速度，第一輪 78，第二輪 103；QAT 版第一輪 94，第二輪 66。只看一輪我就會下錯結論：「QAT 比預設快 20%」。

兩輪的長提示速度卻很穩（96.5 vs 96.2、87 vs 84.8、75.5 vs 74.5）。其他模型兩輪的差距都在 5% 以內，**只有這三個 Gemma 3 4B 的短題速度會飄**，我不知道為什麼。所以：

- 表裡的速度用比較穩的「長提示」那項
- 每個數字至少跑兩輪、看範圍
- 兩輪結論打架的指標，不拿來排名

### 三、功耗是整張卡，不是模型

`nvidia-smi` 量到的是整張卡的功耗，閒置就有 46W。所以「每 token 耗電」是上界，而且 GPU 使用率不到 100%（尤其是小模型）時，模型越小，這個數字越容易被固定耗電拉高。

## 這份實測沒有涵蓋的

- **多人同時問**：網站限制同時最多 2 個在生成，沒有量過兩個請求同時跑的速度
- **更長的 context**：只測了 4,096 和 6,144
- **gpt-oss:20b 之類更大的模型**：約 14GB，這張卡放不下，沒有測
- **品質**：中文品質只有一題的觀察，沒有做系統性的評測
- **電費**：要換算成錢可以用[電費計算器](/tools/power-cost)，但我量的是整卡功耗，不是整台電腦
