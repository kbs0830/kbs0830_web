這個網站跑在我家的桌機上：Windows 工作排程器開機時啟動 Node.js，Cloudflare Tunnel 把外面的流量轉進來，另外有一支 watchdog 每 5 分鐘檢查一次網站，掛了就自動重啟。

聽起來很完整。直到 11/02 在查另一個問題時翻 `server.log`，才發現網站已經對外斷線快 4 天了。

## 先看時間軸

把 log 對起來（台灣時間）：

- **10/29 02:10**　UptimeRobot 最後一次 `HEAD /`，之後就再也沒出現
- **10/29 02:15、02:17**　Next.js server 重新啟動兩次——Windows 的開機時間是 02:16，桌機自己重開機了
- **10/29 ～ 11/02**　沒有任何外面來的請求
- **11/02 01:52**　手動重開 cloudflared，Tunnel 恢復
- **11/02 02:02**　UptimeRobot 的 `HEAD /` 回來了

從 02:15 到隔週 01:52，差 8 分鐘就整整 4 天。

最詭異的是這 4 天的 `server.log` 並不是空的。10/30 一整天的紀錄長這樣：

```
288  GET /
864  GET /_next/static/*
```

288 = 24 小時 × 每小時 12 次，正好是 watchdog 每 5 分鐘打一次首頁、再順便確認 3 個 JS chunk 載得到。**網站本身一直好好的，只是除了 watchdog 自己，沒有人連得進來。**

## 為什麼重開機之後 Tunnel 沒有回來

Cloudflare Tunnel 在 Windows 上可以裝成服務。我裝過，服務也顯示「自動啟動、執行中」。

問題是那個服務的啟動指令**沒有帶任何參數**——只有 `cloudflared.exe`，沒有 `tunnel --config ... run`。它開機會啟動、狀態是 Running，但什麼事都沒做。真正在扛流量的，一直是我手動執行 `start-server.bat` 開出來的那個黑色命令列視窗。

那個視窗掛在我的登入 session 底下。桌機重開機，視窗就沒了；沒人登入去點 bat，就沒人把它開回來。

這件事其實 10/15 就查到了，當時在待辦清單寫了一句「重開機後沒人登入點 bat → Tunnel 不通 → 整站掛」。修法也寫好了，只是要用系統管理員權限跑，一直沒排到。兩週後它就真的發生了。

## 為什麼 4 天都沒有人處理

這才是我比較在意的部分。我有三層監控：兩層沒有叫，叫了的那一層被我忽略了。

1. **watchdog**：它檢查的是 `http://localhost:3000`。從桌機自己的角度，網站完全健康，它也就安靜地每 5 分鐘確認一次「沒事」。它設計成只在異常時寫 log，所以 `watchdog.log` 這 4 天一行都沒有。
2. **UptimeRobot**：它是從外面打的，所以它真的發現了，也真的寄了告警信。我收到了，然後沒管。（順帶一提，它 10 月的月報寫 uptime 0%，明明只斷了 4 天，設定本身也有問題。）
3. **我自己**：網站是我的作品集，我平常不會每天打開自己的網站。

UptimeRobot 那一層沒什麼好分析的，就是我的問題。watchdog 那一層比較值得想一想：它不是壞掉，它完全照設計運作。問題是它回答的問題是「server 有沒有在跑」，而我真正想知道的是「訪客打不打得開」。這兩個問題在大部分時候答案相同，只有在這種時候不一樣——偏偏這種時候才是需要監控的時候。

## 修了什麼

**1. Tunnel 交給 Windows 服務、而且是真的會動的那種。** 寫了一支 `setup-autostart.ps1`，用系統管理員身分把服務的啟動參數補上 `tunnel --config ... run`。順便把排程工作改成「不論使用者是否登入都執行」，不然重開機沒登入的話，連 watchdog 跟自動部署都不會跑。

**2. watchdog 多問一個問題。** localhost 健康之後，再從外網打一次 `https://kbs0830.com/`。這一層失敗代表「server 沒事但外面連不進來」，就寄信給我：

```powershell
# origin 本身壞掉時上面已經處理過，這裡只在 origin 正常時看「外面連不連得進來」
if ($exitCode -eq 0) {
    $public = Test-SiteHealth -Url "https://kbs0830.com/" -MaxWaitSeconds 30
    if (-not $public.Success) {
        $svc = (Get-Service Cloudflared -ErrorAction SilentlyContinue).Status
        Send-Alert -Key "tunnel" -Subject "🔴 外網連不到網站（origin 正常，疑似 Tunnel）" ...
    }
}
```

30 秒內會重試，偶發的網路抖動不會誤報；同一件事 1 小時內只寄一封，恢復時再補一封「已恢復」。只寄信、不自動重啟 Tunnel：一般權限重啟不了 Windows 服務，而且服務本身就有當機自動重啟。

**3. 實際重開機驗證。** 改完設定不算數，要真的重開一次。11/06 找到機會完整重開機、而且不登入：Next.js 開機 20 秒內就起來，Tunnel 大約 2 分 20 秒後恢復（它是「延遲自動啟動」的服務），外網打得開。這次才算真的修好。

## 學到的事

- **「服務在跑」不等於「服務在做事」。** Windows 服務列表的 Running 只代表 process 活著。要確認它真的在工作，要從它應該服務的那一端去看。
- **健康檢查要從使用者的位置做。** 從 localhost 檢查，只能證明 localhost 沒事。
- **只在異常時寫 log 的監控，安靜不代表沒事。** 它也可能只是在檢查一件沒出問題的事。
- **告警寄出來沒人處理，跟沒有告警一樣。** 現在 watchdog 自己寄的信會直接寫「哪裡壞了、是不是還需要人處理」，Tunnel 那封還附上先試哪個指令——至少讓自己沒有藉口說看不懂。
- **寫在待辦清單上的「重開機會壞」不會自己消失。** 它只是在等一次重開機。
