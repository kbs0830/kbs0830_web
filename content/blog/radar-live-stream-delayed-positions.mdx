[自家雷達](/radar)這個頁面從一開始就有一條規矩：**只放數字，不放位置**。現在幾架、今天幾架、哪些航空公司，這些都行；飛機的座標、離接收器多遠，一律不存。原因很單純：把收到的飛機位置畫出來，圓心就是接收器，也就是我家。

後來想把它做成 YouTube 的 24 小時直播，用 OBS 抓網頁當畫面。直播沒有地圖和飛機就沒什麼好看的，所以這條規矩要鬆一點。這一天的改動很多，我照時間順序記下來：每一次放寬，都是我自己決定的。

## 一開始的規則：先延遲、不標接收器

- **大概在高雄**可以說，更細的不說。
- 飛機位置可以放，但要**延遲 5 分鐘**：沒辦法拿來即時追蹤，也很難靠「這一刻能收到哪些飛機」反推接收範圍。
- 地圖固定在高雄周邊，**不以接收器為中心**、不畫距離圈、不標接收器位置。
- 其他頁面（`/radar`、`/api/radar`）的規則完全不變，放出座標的只有一個新的 API 跟一個新的頁面。

後來這些數字都改了，但「規則寫在資料出口、數字放在常數裡」這個做法一直沒變：`DELAY_MS` 一行，延遲就從 5 分鐘改成 1 分鐘，再改成 0。

## 資料怎麼流

網站伺服器本來就會定時讀接收器。我多加一支 `radar-live.js`，每次讀完順便把當下每架飛機的位置、速度、航向存進 `data/radar-track.json`，**只留最近 20 分鐘**，更舊的直接丟。

對外的 `/api/radar/live` 只給「現在時間減延遲」以前的取樣。單元測試專門驗這件事：造一串取樣，確認比截止時間新的一筆都不會出現在輸出裡。

另外的處理：

- **識別碼不外流。** 接收器回來的 ICAO hex 是飛機的識別碼，API 只回一個每次啟動重新產生金鑰的 HMAC 縮短碼。一開始我用「hex＋日期」直接雜湊，後來才想到 hex 只有 24 位元，單純雜湊可以暴力還原，所以改成 HMAC。
- **註冊號、所屬公司、製造商只給有正常航班代碼的商用航班。** 私人機的所屬人可能是個人姓名，沒班號的一個欄位都不帶。
- **座標粗化到小數三位**，約 100 公尺。

## 延遲改 0、取樣改 5 秒、讀接收器改 5 秒

開播之後我先把延遲縮到 1 分鐘，接著決定乾脆改成 0。延遲 0 的畫面如果還是 30 秒一筆資料，飛機會一跳一跳，所以取樣也跟著改：

- 伺服器讀接收器從 **30 秒改成 5 秒**（統計和直播軌跡共用同一次讀取）。
- 問外面的 adsbdb 查機型不跟著變快：每 6 次才做一次，不然請求量變 6 倍。
- 畫面用 canvas，播放時間設成「現在 − 延遲 − 一小段緩衝」，兩筆取樣之間線性內插，後面沒有新取樣就用速度和航向外推，最多推 75 秒。尾跡畫最近 5 分鐘，越舊越淡。

同一天我也把低空、地面、高度不明的位置的過濾拿掉了。原本這條規則是：低空航跡會透露離機場、也就離接收器多近，所以只放高度已知且 1,000 ft 以上的（中間一度寫成「高度不明就放行」，自動資安檢查指出這是 fail open，改成 fail closed）。後來決定畫面要完整顯示，這條就拿掉了，連同測試一起改。

留下來的規則：地圖不以接收器為圓心、不畫距離圈、不標接收器；掃描線的圓心放在高雄市區，只是氣氛，不是資料。

## 沒有座標的飛機

有一次我發現有兩班飛機沒有出現在畫面上。查資料才知道：接收器有聽到（今天的統計有算），但只收到部分訊號、沒有解出座標，所以地圖畫不出來。這種飛機現在只要有正常班號，就會列進右欄的「剛剛經過」，只是不在地圖上。

「剛剛經過」的紀錄留 24 小時、沒有筆數上限，畫面依區塊高度放得下幾列就顯示幾列，不會被切一半。

## 海岸線與縣市界不用地圖服務

底圖不想依賴外部地圖服務（直播要穩，也不想在畫面裡留一堆圖資授權字樣）：

- 海岸線：Natural Earth 10m 陸地資料，用 Sutherland–Hodgman 裁出高雄周邊、Douglas–Peucker 簡化，32 個多邊形、約 700 個點、11 KB。
- 縣市界：g0v 的 taiwan-atlas，只取兩個縣市共用的內部界線（海岸線已經有了），8 KB，畫成虛線。
- 機場、跑道、導航台：OurAirports（公有領域）。

裁海岸線時踩到一個小坑：Douglas–Peucker 遇到首尾同點的封閉環，起點跟終點重合，每個點到「這條線」的距離都是 0，整個環被簡化成 2 個點，結果一個多邊形都沒留下。解法是把環從中間切成兩段各自簡化再接起來。

## canvas 的 font 不認 CSS 變數

地圖上的城市名和航班標籤一開始怎麼調大小都沒反應。原因是我寫成：

```ts
ctx.font = `17px var(--font-mono), monospace`;
```

canvas 的 `font` 屬性**不會解析 CSS 變數**，整行不合法，瀏覽器就默默忽略，字型維持預設的 10px。要先用 `getComputedStyle(canvas).getPropertyValue("--font-mono")` 把真正的字型名稱讀出來再組字串。這個錯不會有任何錯誤訊息，只有看截圖才發現「怎麼字都沒變大」。

## OBS 不算訪客、也不會自己刷新

網站有造訪計數和「いま N 人」。OBS 的瀏覽器來源一直開著，不處理的話會變成永遠在線的一位訪客。直播頁在這兩個回報元件裡直接跳過；頁面也設 `noindex`，robots 擋掉，不放進 sitemap。

另一個問題是 OBS 的瀏覽器來源**不會自己重新整理**：我每部署一次新版，OBS 裡跑的還是舊版畫面。解法是 `/api/radar/live` 回一個 `build`（這次部署的 commit），畫面記住第一次看到的值，之後變了就自己 `location.reload()`，並隨機等 0–8 秒。舊版畫面沒有這段，所以第一次要手動刷新一次，之後才會自己更新。

## 音量條：OBS 瀏覽器來源讀不到麥克風

直播要放音樂，我想在畫面左側放一條音量條，讓人看得出有聲音。第一版用瀏覽器的 `getUserMedia` 讀「音訊輸入」，搭配虛擬音效線（VB-Cable）：音樂播放器輸出到虛擬線，OBS 和網頁都讀這條線的輸出。

在一般 Chrome 裡完全正常，換到 OBS 的瀏覽器來源就是 `NotAllowedError: Permission denied`——OBS 內嵌的瀏覽器不允許網頁讀麥克風。所以改走另一條路：

- OBS 內建 WebSocket 伺服器（工具 → WebSocket 伺服器設定），訂閱 `InputVolumeMeters` 事件，會持續回報混音器裡每個來源的音量。
- 網頁連 `ws://localhost:4455`，Hello → Identify（有密碼時用 `sha256(sha256(密碼+salt)+challenge)` 驗證），讀名稱符合的來源的音量，換成 dBFS 畫成 24 格。
- 不需要麥克風權限，也不需要虛擬音效線。
- 網站的 CSP 只對這一頁多放行 `connect-src ws://localhost:*`，麥克風的 Permissions-Policy 也只對這一頁放行，其他頁照舊全關。

測試的時候沒有真的 OBS，用 Playwright 的 `routeWebSocket` 在頁面裡模擬 OBS 的訊息，涵蓋無密碼、密碼正確、沒給密碼、來源名稱打錯四種情況。

## 部署：從 5–7 分鐘到一分多鐘

直播的畫面一直在改，部署的等待就變得很煩。我量了一下時間花在哪：

- push 同時觸發 E2E 和部署，全站只有一台 self-hosted runner，部署要排在 E2E（約 5–7 分鐘）後面。**E2E 改成手動觸發之後，部署只剩約 70 秒。**（代價是 push 後沒有 E2E 把關，改動要自己先在測試埠驗過。）
- 剩下的 70 秒裡，編譯就佔 20 秒。log 一直寫著 `No build cache found`：`deploy.ps1` 每次 build 前把整個 build 資料夾刪掉，連 Turbopack 放在裡面的編譯快取一起刪了。改成只清掉 `cache` 以外的東西，兩個 build 槽輪流用，每個槽的快取隔一次部署就用得上。

## 學到的事

- 隱私規則要寫在**資料出口**，不要只靠畫面端。最後會公開的是 API 的輸出，畫面怎麼畫是之後的事。
- 規則是會改的：延遲從 5 分鐘縮到 1 分鐘再到 0，高度過濾也拿掉。把數字放在常數、規則寫在檔案開頭，改起來才不會漏。
- 「這個環境能不能用」要在目標環境裡驗：麥克風在 Chrome 能用、在 OBS 不能用，只有在 OBS 裡看到錯誤文字才知道。診斷文字（`NotAllowedError`）比猜測有用得多。
- 部署慢先量時間花在哪：一半以上是排隊，剩下的一部分是每次都丟掉可以留的快取。
